NetwMultiplayer
===============

**Inherits:** :godot:`MultiplayerAPIExtension`

The :godot:`MultiplayerAPI` implementation for a Networked session.

.. rst-class:: classref-introduction-group

Description
-----------

Use :ref:`Netw.of()<class_Netw_method_of>` to get it for a node. Its methods take the :godot:`RID` of an object such as a :ref:`NetwEntity<class_NetwEntity>` or a :ref:`NetwScene<class_NetwScene>`, and most game code uses those objects instead.

::

    var api := Netw.of(self)
    api.entity_despawn(NetwEntity.of(self).rid)
    api.scene_watch(Netw.scene(self).rid, player.id)

\ Each method prefix matches the class that wraps it.

- ``session_*`` and ``stats_*``: :ref:`NetwSession<class_NetwSession>`\

- ``transport_*``: :ref:`NetwTransport<class_NetwTransport>`\ 

- ``rpc_*`` and ``sync_*``: :ref:`NetwMemberConfig<class_NetwMemberConfig>`\

- ``database_*`` and ``persist_*``: :ref:`NetwDatabase<class_NetwDatabase>` and :ref:`NetwPersistence<class_NetwPersistence>`\ 

The ``player_*`` methods take or return a player id, which the session gives each player when its join is accepted. The id stays the same across a server transfer. Another session, such as one under a second :ref:`MultiplayerViewport<class_MultiplayerViewport>`, gives out its own ids, so the same number names a different player there or none.

.. _class_NetwMultiplayer_property_auth_timeout:

.. rst-class:: classref-property

:godot:`float` **auth_timeout** = ``3.0`` :ref:`🔗<class_NetwMultiplayer_property_auth_timeout>`

.. rst-class:: classref-property-setget

- |void| **set_auth_timeout**\ (\ value\: :godot:`float`\ )
- :godot:`float` **get_auth_timeout**\ (\ )

Seconds a peer has from connecting until a link is admitted, or ``0`` for no limit. On the server it is a joining client's deadline unless :ref:`NetwAdmissionConfig.timeout()<class_NetwAdmissionConfig_method_timeout>` is declared, and the server tells the client that deadline. A client uses its own value until the server first replies, and on links to other clients. A join that passes its deadline is refused with :godot:`@GlobalScope.ERR_TIMEOUT <@GlobalScope#class_@GlobalScope_constant_ERR_TIMEOUT>`.

.. _class_NetwMultiplayer_method_event_drain:

.. rst-class:: classref-method

:godot:`PackedInt64Array` **event_drain**\ (\ ) :ref:`🔗<class_NetwMultiplayer_method_event_drain>`

Returns and clears the rows recorded since the last call, oldest first. The session keeps the newest 4096 rows, so drain once a frame while armed.

::

    func _physics_process(_delta: float) -> void:
        var rows := api.event_drain()
        for at in range(0, rows.size(), NetwMultiplayer.EVENT_ROW_WIDTH):
            if rows[at] == NetwMultiplayer.EVENT_DESPAWNED:
                print("despawned route ", rows[at + 3])

\ A row is :ref:`EVENT_ROW_WIDTH<class_NetwMultiplayer_constant_EVENT_ROW_WIDTH>` values, and its :ref:`Event<enum_NetwMultiplayer_Event>` kind says what ``a`` and ``b`` hold. The entity is the id of its :ref:`NetwEntity.rid<class_NetwEntity_property_rid>`, as :godot:`RID.get_id() <RID#class_RID_method_get_id>` returns it, and the route is what :ref:`entity_get_route()<class_NetwMultiplayer_method_entity_get_route>` returns on every peer.

.. code:: text

    PackedInt64Array
    ┖╴row
      ┠╴kind     int  an Event value
      ┠╴tick     int  the tick it happened on
      ┠╴entity   int  the entity's RID id, 0 when it concerns none
      ┠╴route    int  the entity's route, 0 when it concerns none
      ┠╴peer     int  the peer it concerns, 0 when none
      ┠╴verdict  int  an Error, OK unless the kind judges something
      ┖╴a, b     int  two values that depend on kind, 0 when unused
        ┠╴EVENT_STAGE_TRANSITION     a the stage left, b the stage entered
        ┠╴EVENT_CONTROL_CHANGED      a the peer before, b the peer after
        ┠╴EVENT_CONTROL_REQUESTED    peer is the requester
        ┠╴EVENT_INTEREST_ENTER,
        ┃ EVENT_INTEREST_EXIT,
        ┃ EVENT_OBSERVER_ENTERED,
        ┃ EVENT_OBSERVER_LEFT        a the layer's RID id, peer the observer
        ┠╴EVENT_PREDICT_CONSUME      a the queue depth, b the buffer
        ┠╴any other kind from
        ┃ EVENT_EPISODE_OPEN to
        ┃ EVENT_RECOVERY             a the prediction transition
        ┠╴EVENT_SYNC_ENCODE          a the bytes written
        ┠╴EVENT_GATHER               a the rows offered, b the rows sent
        ┠╴EVENT_APPLY                a the frames applied
        ┠╴EVENT_TABLE_COMMIT         a the rows committed
        ┠╴EVENT_DISPLAY_RECORD       a the tick of the sample
        ┠╴EVENT_DISPLAY_PUMP         a the display tick
        ┠╴EVENT_DATAGRAM_SENT        a the size, b the sequence
        ┠╴EVENT_DATAGRAM_RECEIVED    a the size, b the sequence or -1 when reliable
        ┠╴EVENT_DATAGRAM_MALFORMED   a the size
        ┖╴EVENT_ACK_ADVANCED         a the newest sequence acknowledged

.. _class_NetwMultiplayer_method_lagcomp_action_request:

.. rst-class:: classref-method

:godot:`Error <@GlobalScope#enum_@globalscope_Error>` **lagcomp_action_request**\ (\ key\: :godot:`StringName`, target\: :godot:`NodePath`, method\: :godot:`StringName`, view_tick\: :godot:`int`, args\: :godot:`Array` = [], timing\: :ref:`TimingMode<enum_NetwAction_TimingMode>` = 2\ ) :ref:`🔗<class_NetwMultiplayer_method_lagcomp_action_request>`

Sends ``method`` with ``args`` to the server, which calls it on the node at ``target``, a path from the session's root node, as the world was at ``view_tick``. ``timing`` picks when the server runs it. On a server, a host or an offline session the action runs and resolves ``key`` before this returns, so :ref:`lagcomp_effect_arm()<class_NetwMultiplayer_method_lagcomp_effect_arm>` and :ref:`lagcomp_effect_watch()<class_NetwMultiplayer_method_lagcomp_effect_watch>` are called for ``key`` first. Returns :godot:`@GlobalScope.ERR_BUSY <@GlobalScope#class_@GlobalScope_constant_ERR_BUSY>` while the session applies its settings.

::

    var key := api.lagcomp_action_key(entity, tick)
    api.lagcomp_effect_arm(key, revert)
    api.lagcomp_effect_watch(key, confirmed, denied)
    api.lagcomp_action_request(key, target, &"fire", tick, [aim])

\ **Player request.**

.. _class_NetwMultiplayer_method_peer_get_link_stats:

.. rst-class:: classref-method

:godot:`Dictionary` **peer_get_link_stats**\ (\ peer\: :godot:`int`\ ) |const| :ref:`🔗<class_NetwMultiplayer_method_peer_get_link_stats>`

Returns measured connection quality to ``peer``, and what this peer's byte budget sends it.

.. code:: text

    Dictionary
    ┠╴loss           float   share of the last 32 packets lost
    ┠╴rtt            float   round trip time, in seconds
    ┠╴jitter         float   round trip variation, in seconds
    ┠╴reorders       int     packets that arrived out of order
    ┠╴duplicates     int     packets that arrived twice
    ┠╴mode           String  "good", or "bad" while its budget is cut
    ┠╴budget_bits    int     most bits one packet to this peer may use
    ┠╴budget_bytes   int     bytes it may be sent each tick
    ┠╴sent_bytes     int     bytes charged to it since it joined
    ┠╴debt_bytes     int     bytes it was sent past its budget
    ┖╴deferred_rows  int     rows left waiting by the last tick

\ Losing packets halves ``budget_bytes`` and ``budget_bits``. Each round trip without loss adds back an eighth of the configured budget, stopping an eighth short of the rate that lost packets for the next minute. While ``debt_bytes`` is above zero, volatile properties wait, and retained properties and RPCs still go.

.. _class_NetwMultiplayer_method_transport_create_peer:

.. rst-class:: classref-method

:godot:`RID` **transport_create_peer**\ (\ transport\: :godot:`RID`, mode\: :ref:`TransportMode<enum_NetwConnection_TransportMode>`, address\: :godot:`String`, settings\: :godot:`Dictionary`, completed\: :godot:`Callable`\ ) :ref:`🔗<class_NetwMultiplayer_method_transport_create_peer>`

Asks ``transport`` to create a :godot:`MultiplayerPeer` and returns a ticket for :ref:`transport_cancel_peer_creation()<class_NetwMultiplayer_method_transport_cancel_peer_creation>`. ``address`` is used by clients and ``settings`` by hosts.

\ ``completed`` is called once, in a later frame, as ``completed(peer, error, detail)``. Assign the peer to :godot:`MultiplayerAPI.multiplayer_peer <MultiplayerAPI#class_MultiplayerAPI_property_multiplayer_peer>` inside this callback, before any ``await``. Returning without assigning it closes the peer.

Returns an invalid :godot:`RID` when ``completed`` is not valid.

::

    var ticket := api.transport_create_peer(
            relay, NetwConnection.TRANSPORT_MODE_CLIENT,
            "eu-1.example.com", {}, _created)

    func _created(peer: MultiplayerPeer, error: Error, _detail: String):
        if error != OK:
            return
        api.multiplayer_peer = peer

.. _class_NetwMultiplayer_method_transport_register:

.. rst-class:: classref-method

:godot:`RID` **transport_register**\ (\ type\: :godot:`Script`\ ) :ref:`🔗<class_NetwMultiplayer_method_transport_register>`

Registers the :ref:`NetwTransport<class_NetwTransport>` script ``type`` with this session. Registering it again returns the same :godot:`RID`. Returns an invalid :godot:`RID` when another script is already registered for the same peer class. It replaces the built-in transport of that class.

::

    func _ready() -> void:
        var api := Netw.of(self)
        var relay := api.transport_register(MyRelayTransport)
        var caps: int = api.transport_get_param(
                relay, NetwMultiplayer.TRANSPORT_PARAM_CAPABILITIES)

:godot:`Error <@GlobalScope#enum_@globalscope_Error>` **transport_unregister**\ (\ transport\: :godot:`RID`\ ) :ref:`🔗<class_NetwMultiplayer_method_transport_unregister>`

Reverses :ref:`transport_register()<class_NetwMultiplayer_method_transport_register>`. A peer it already created stays connected.     # ... later, when the relay SDK is shut down

.. code:: text

    Error
    ┠╴OK                  the transport was removed
    ┖╴ERR_DOES_NOT_EXIST  not registered on this session
