NetwSimulation
==============

**Inherits:** :godot:`RefCounted`

Where and how one :ref:`NetwEntity<class_NetwEntity>`'s body runs on each peer.

.. rst-class:: classref-introduction-group

Description
-----------

Reached through :ref:`NetwEntity.simulation<class_NetwEntity_property_simulation>`. Each peer runs the entity in one :ref:`mode<class_NetwSimulation_property_mode>`, which decides whether :ref:`network_process<class_NetwSimulation_property_network_process>` runs and whether the body is frozen. A game sets the members below and reads :ref:`mode<class_NetwSimulation_property_mode>`.

\ 

An entity is simulated once it sets or calls anything here, is predicted as :ref:`NetwPrediction<class_NetwPrediction>` describes, or has a :godot:`RigidBody2D` or :godot:`RigidBody3D` root drawn by :ref:`NetwEntity.display<class_NetwEntity_property_display>`. Other entities stay :ref:`MODE_NONE<class_NetwSimulation_constant_MODE_NONE>`.

\ **Modes**\ 

The peer writing replicated state runs :ref:`MODE_AUTHORITY<class_NetwSimulation_constant_MODE_AUTHORITY>`. A predicting client runs :ref:`MODE_PREDICT<class_NetwSimulation_constant_MODE_PREDICT>`. Every other copy is :ref:`MODE_PROXY<class_NetwSimulation_constant_MODE_PROXY>` or :ref:`MODE_ACTIVE<class_NetwSimulation_constant_MODE_ACTIVE>`, as :ref:`remote_mode<class_NetwSimulation_property_remote_mode>` says.

.. _class_NetwSimulation_property_bodies:

:godot:`Array`\[:godot:`NodePath`\] **bodies** :ref:`🔗<class_NetwSimulation_property_bodies>`

.. rst-class:: classref-property-setget

- |void| **set_bodies**\ (\ value\: :godot:`Array`\[:godot:`NodePath`\]\ )
- :godot:`Array`\[:godot:`NodePath`\] **get_bodies**\ (\ )

The physics bodies this entity runs, as paths from the entity root. They are frozen on a :ref:`MODE_PROXY<class_NetwSimulation_constant_MODE_PROXY>` copy. A root that is a :godot:`RigidBody2D` or :godot:`RigidBody3D` is always included, and a path to any other kind of node is skipped.

Set it before the entity enters the tree, such as in ``_init``. The bodies are read once, soon after the entity enters the tree, and a write after that warns once and is ignored.

.. _class_NetwSimulation_property_claim_on_contact:

.. rst-class:: classref-property

:godot:`bool` **claim_on_contact** :ref:`🔗<class_NetwSimulation_property_claim_on_contact>`

.. rst-class:: classref-property-setget

When a body of this entity runs here as :ref:`MODE_AUTHORITY<class_NetwSimulation_constant_MODE_AUTHORITY>` and touches a free entity that also sets it, this peer claims that entity with :ref:`NetwEntity.HOLD_SOFT<class_NetwEntity_constant_HOLD_SOFT>`. A claimed entity claims what it touches in the same tick.

It raises :godot:`RigidBody3D.max_contacts_reported <RigidBody3D#class_RigidBody3D_property_max_contacts_reported>` on the bodies. :godot:`RigidBody3D.body_entered <RigidBody3D#class_RigidBody3D_signal_body_entered>` and :godot:`RigidBody3D.body_exited <RigidBody3D#class_RigidBody3D_signal_body_exited>` need the game's own :godot:`RigidBody3D.contact_monitor <RigidBody3D#class_RigidBody3D_property_contact_monitor>`. It needs :ref:`NetwEntity.TRANSFER_IMMEDIATE<class_NetwEntity_constant_TRANSFER_IMMEDIATE>` on an entity with no :ref:`NetwPropertyConfig.state()<class_NetwPropertyConfig_method_state>` property and no prediction, and does nothing otherwise.

.. _class_NetwSimulation_property_network_process:

.. rst-class:: classref-property

:godot:`Callable` **network_process** :ref:`🔗<class_NetwSimulation_property_network_process>`

.. rst-class:: classref-property-setget

- |void| **set_network_process**\ (\ value\: :godot:`Callable`\ )
- :godot:`Callable` **get_network_process**\ (\ )

Called each tick while :ref:`mode<class_NetwSimulation_property_mode>` runs the body. Defaults to the root's ``_network_process``.

::

    func _network_process(delta: float, tick: int, is_fresh: bool) -> void:

\ ``is_fresh`` is ``true`` the first time a tick runs. It is ``false`` when a rollback runs the tick again and on a :ref:`MODE_ACTIVE<class_NetwSimulation_constant_MODE_ACTIVE>` copy, so play sounds and spawn nodes only when it is ``true``.

Ask the physics space with a query. An :godot:`Area3D`'s overlaps and signals and :godot:`CharacterBody3D.is_on_floor() <CharacterBody3D#class_CharacterBody3D_method_is_on_floor>` come from the last physics step, and a rollback restores neither.

.. _class_NetwSimulation_property_physics_driven:

.. rst-class:: classref-property

:godot:`bool` **physics_driven** :ref:`🔗<class_NetwSimulation_property_physics_driven>`

.. rst-class:: classref-property-setget

- |void| **set_physics_driven**\ (\ value\: :godot:`bool`\ )
- :godot:`bool` **get_physics_driven**\ (\ )

If ``true``, the physics server moves this entity, so one with a :ref:`NetwPropertyConfig.state()<class_NetwPropertyConfig_method_state>` property is predicted without a :ref:`network_process<class_NetwSimulation_property_network_process>`. Defaults to ``true`` when the root or a body in :ref:`bodies<class_NetwSimulation_property_bodies>` is a :godot:`RigidBody2D` or :godot:`RigidBody3D`.

While such an entity is predicted, :godot:`RigidBody3D.max_contacts_reported <RigidBody3D#class_RigidBody3D_property_max_contacts_reported>` is raised to ``8`` on its bodies so their contacts can be read.
